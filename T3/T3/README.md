## 任务背景

你的作业清单越来越长。今天先做哪一项？只看数学时，还能把数学作业调整到自己想要的顺序吗？请通过与 Agent 对话改造这个真实 TodoMVC 小项目，让它支持给作业选科目、按科目查看和上下移动，刷新后仍记得安排。

初始项目已能添加、勾选、删除和清理作业。科目筛选与上移、下移控件已准备好，**但功能尚未实现**；当前数据只在内存中，刷新会丢失。

## 功能要求

1. **保留原功能**：在输入框按 Enter 添加，去掉标题两端空白，空标题不添加。同名作业是不同的条目。每条都能单独勾选完成或取消、删除；“清理已完成”删除全清单中的已完成条目，包括当前筛选看不到的。原来的“全部/未完成/已完成”继续有效，剩余数字一直是**全清单**未完成的条数。
2. 每条作业有四种科目：**未分类、语文、数学、英语**。新作业一律是未分类，未完成，并追加到全清单末尾。**即使正在只看数学，也不把新作业自动归为数学。**
3. 每行科目下拉框显示该条当前科目。修改时**只改这一条**的科目，标题、完成情况、其他条目和全清单顺序不变。同名作业也要能分别选科目。如果它不再符合当前筛选，应立即从当前视图消失。
4. 顶部科目筛选有“全部科目”和上面的四种科目。它与完成筛选**同时生效**：例如“数学+未完成”只显示未完成的数学作业。切换任何筛选都不改变作业或全清单顺序。
5. 每条可见作业有“上移”和“下移”。上移只与**当前可见的上一条**交换，下移只与**当前可见的下一条**交换。交换的是这两条在全清单中的位置，其他条目的位置保持，作业的标题、完成情况、科目跟着它本人走。
6. 当前可见的第一条上移按钮禁用，最后一条下移按钮禁用；只有一条时两个都禁用。没有可见条目时列表为空，科目筛选仍能使用。修改科目、勾选完成、删除、清理或切换筛选后，按钮状态随新的可见顺序更新。
7. **浏览器刷新后**，恢复全清单的标题、完成情况、科目与顺序；之后添加作业仍追加末尾，不与已有条目混淆。使用浏览器本地存储，不调用外网。不要求刷新后保留筛选选项；你可以恢复为全部，也可以保留当前筛选。刷新不会增加、丢失或重复条目。
8. 每次正常操作后的界面变化在 **1 秒内**可见。本题输入最多 8 条作业，标题不超过 80 字符；测试使用普通中文、英文、同名标题和标点。存储从空白开始或来自本题自己之前的正常操作，不考损坏存储、跨标签页同步或旧版本数据迁移。没有撤销、搜索或批量操作要求。

## 一个操作例子

全清单依次是 A（数学），B（英语），C（数学），D（未分类）。只看数学时显示 A，C。点 C 的“上移”后：数学视图为 C，A，全清单为 C，B，A，D。B、D 的位置没有动。再点 C 的“上移”不能继续，因为它已经是当前可见的第一条。

如果把当前可见的 C 改为英语，数学视图就只剩 A；C 在全清单里的位置保持。改回“全部科目”仍显示 C，B，A，D。刷新后，科目与这个顺序仍在。

## 你怎样与 Agent 协作

用自然语言告诉 Agent 要实现的行为，也可以补充例子、指出问题并要求它检查相关代码。Agent 具备 **read_file、write_file、bash** 三个工具，可以在本题离线工作区读取和修改文件、执行项目内命令。工具由 Agent 使用，考生不操作终端。

你可以查看平台提供的页面预览、文件变化和用量记录；**只能通过与 Agent 对话修改作品**，不能使用文件编辑器、命令行或外部工具直接改代码或测试内容。模型和 Agent 的配置由考场统一提供，不开放切换。

## 项目与操作约定

可以让 Agent 修改 `index.html`、`src/`、`assets/`，或在后两个目录新增源码和样式文件。**题面、来源说明、许可证、启动脚本及测试内容固定。** 作品须保留提供的页面入口，使用已提供的离线资源。

布局、配色、内部函数和保存格式由你通过 Agent 安排；**按功能评分，不按像素或修改文件数评分**。为了平台能定位操作位置，请让 Agent 保留下表控件及用途。

| 控件 | 定位约定 |
| --- | --- |
| 新作业输入框 | `.new-todo`，按 Enter 添加 |
| 可见作业行 | `.todo-list > li`；每条有唯一 `data-id`；标题在行内 `label` |
| 完成框 / 删除按钮 | 行内 `.toggle` checkbox / `.destroy` button |
| 清理 / 未完成数 | `.clear-completed` / `.todo-count strong` |
| 完成状态筛选 | `.filters a`，链接为 `#/`、`#/active`、`#/completed` |
| 顶部科目筛选 | `select#subject-filter`；value 为 `all`、`unassigned`、`chinese`、`math`、`english` |
| 行内科目 | `select.task-subject`；value 为 `unassigned`、`chinese`、`math`、`english` |
| 移动按钮 | 行内 `button.move-up` / `button.move-down`；边界使用原生 `disabled` |

可移除不匹配筛选的行，也可用 CSS 隐藏。平台只按可见行判断顺序。移动按钮禁用时仍显示在行内；正常操作需要的控件须可见、可用，科目和按钮文字要能辨认。

## 用量与提交评分

模型与 Agent 用量：每次模型输出最多 8,192 Token；每条学生消息最多触发 4 次模型请求，整题最多 80 次请求。Agent 完成这一轮后暂停，你可以继续对话。单条工具命令最长 60 秒；工作区不能联网。

A=100,000 Token，B=160,000 Token，K=50%（暂定）。累计实际输入和输出用量为 T，十个测试点得到的功能原分为 S：

| 累计用量 | 最终得分 |
| --- | --- |
| T ≤ 100,000 | S |
| 100,000 < T ≤ 160,000 | S × [1 − 0.5 × (T − 100,000) / 60,000] |
| 到达 B | 停止模型调用，保留当前作品；用量系数为 50% |

例如功能原分 S=80：T=100,000 时得 80 分，T=130,000 时得 60 分，T=160,000 时得 40 分。最终只四舍五入一次，保留两位小数。

提交与自动测试：

1. 完成作答后点击“提交”。平台停止 Agent 和工具，锁定当前项目及同一时刻的累计用量。提交后不能继续改动作品。达到时间或预算上限时，也冻结当前作品。
2. 平台自动运行 5 个公开测试点，现场展示每点的实际结果、预期结果及差异。你无需点击“运行测试”、输入测试命令或自行修改测试内容。公开功能分满分 50。
3. 另 5 个隐藏点的输入、操作、预期和成绩在考试时完全不展示；考试结束后，对同一份锁定项目统一评测。隐藏部分满分 50。
4. 最终公开与隐藏共 10 点，每点 10 分，总功能分 100。**每点包含两个独立子场景，所有操作和预期全部通过才得 10 分**，不按单条断言给部分分。隐藏点只检查题面已写出的行为。初始项目未实现新增功能，直接提交得不到功能分。
